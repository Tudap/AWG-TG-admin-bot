Легковесный, производительный и безопасный Telegram-бот на **TypeScript** и среде выполнения **Bun** для персонального администрирования сервера **AmneziaWG (AWG)**.

Бот выступает удобным мобильным интерфейсом поверх консольного скрипта [`manage_amneziawg.sh`](https://github.com/bivlked/amneziawg-installer) и обеспечивает полный цикл управления пирами, автоматический патчинг клиентских конфигураций, замер доступности из РФ и создание резервных копий.

## ✨ Ключевые особенности

### 🛡 Безопасность и изоляция
* **Strict Admin Middleware:** Бот обрабатывает сообщения **только** от указанного в `.env` Telegram User ID (`ADMIN_ID`). Сообщения и нажатия кнопок от любых других пользователей молча сбрасываются (drop update) без ответа и утечки метаданных.

### 👥 Управление клиентами (FSM)
* **Пошаговый мастер создания:** Интерактивный диалог добавления нового пира с валидацией имени (`^[a-zA-Z0-9_]{1,32}$`).
* **Гибкие сроки доступа:** Возможность выпустить как **бессрочный** доступ, так и временный на **1 день** (`--expires=1d`), **7 дней** (`--expires=7d`) или **30 дней** (`--expires=30d`).
* **Мгновенная выдача (Dual-Delivery):** 
  * QR-код генерируется библиотекой `qrcode` **строго в оперативной памяти** (`Buffer`) и отправляется как фото (`replyWithPhoto`) без создания временных файлов на диске.
  * Файл конфигурации `.conf` отправляется документом (`replyWithDocument`).
* **Перевыпуск и повторное скачивание (Regen):** В любой момент можно заново получить QR-код и файл конфигурации для существующего клиента в один клик.
* **Безопасное удаление:** Удаление пира сопровождается подтверждением действия во избежание случайных нажатий.
* **Пагинация:** Удобный постраничный список клиентов с цветовой индикацией статуса:
  * 🟢 — постоянный активный доступ
  * ⏱ — временный доступ со сроком действия
  * 🔴 — истекший доступ

### 🔧 Автоматический патчинг конфигураций
Каждый сгенерированный или перевыпущенный файл конфигурации `.conf` автоматически модифицируется модулем `patcher.ts` перед отправкой и сохранением на сервере:
1. `AllowedIPs` строго заменяется на `0.0.0.0/0` (маршрут IPv6 `::/0` полностью вырезается во избежание утечек и проблем с DNS/IPv6 на мобильных устройствах).
2. `PersistentKeepalive` принудительно выставляется в `15` для стабильного поддержания NAT-сессии за сотовыми операторами.

### 📊 Диагностика и статистика
* **Статус и трафик:** Отображение параметров интерфейса (`awg0`), объема переданного/принятого трафика (в `B`, `KB`, `MB`, `GB`) и времени последнего рукопожатия (Handshake) по каждому пиру.
* **Здоровье сервера:** Локальная диагностика интерфейсов, фаервола и сетевых политик через системный вызов `check`.
* **Тест доступности из РФ (Globalping API):** Внешний замер пинга и потерь пакетов из нескольких городов России (Москва, Санкт-Петербург и др.) через зонды Globalping для оперативной проверки блокировок РКН / ТСПУ.

### 💾 Резервное копирование
* Создание резервной копии сервера (`manage_amneziawg.sh backup --json`) с отправкой сжатого архива `.tar.gz` прямо в чат администратору.

## ⚡ Архитектура Zero-DB

В проекте **принципиально не используются внешние СУБД** (ни SQLite, ни PostgreSQL, ни Redis):
- Единственным источником истины (Single Source of Truth) является системный скрипт `/usr/local/bin/manage_amneziawg.sh`.
- Все операции чтения и модификации выполняются напрямую через Bun Shell (`Bun.$`) с флагом `--json`.
- Это исключает рассинхронизацию базы данных с состоянием WireGuard-интерфейса, не требует миграций и гарантирует минимальное потребление RAM (менее 30-40 MB).

## 🖥 Требования к серверу

1. **ОС:** Ubuntu 20.04/22.04/24.04 LTS или Debian 11/12.
2. **Скрипт управления AmneziaWG:** Установленный скрипт от [bivlked/amneziawg-installer](https://github.com/bivlked/amneziawg-installer) по пути `/usr/local/bin/manage_amneziawg.sh`.
3. **Среда выполнения:** [Bun](https://bun.sh/) (версия 1.0.0 или выше).
4. **Telegram:** Зарегистрированный бот через [@BotFather](https://t.me/BotFather) и ваш цифровой ID из [@userinfobot](https://t.me/userinfobot).

## 🚀 Быстрый старт

### 1. Установка Bun

Если Bun еще не установлен на сервере:

```bash
curl -fsSL https://bun.sh/install | bash
source ~/.bashrc
```

Проверьте установку:

```bash
bun --version
```

### 2. Клонирование и установка зависимостей

```bash
cd /opt
git clone https://github.com/Tudap/AWG-TG-admin-bot.git awg-bot
cd awg-bot
bun install
```

### 3. Настройка переменных окружения

Скопируйте шаблон конфигурации:

```bash
cp .env.example .env
nano .env
```

Заполните переменные:

```env
# Токен бота, полученный от @BotFather
BOT_TOKEN=1234567890:AAExampleSecretTokenHere

# Ваш числовой Telegram User ID (узнать в @userinfobot)
ADMIN_ID=123456789

# Путь к скрипту управления AmneziaWG
AWG_SCRIPT=/usr/local/bin/manage_amneziawg.sh

# Публичный IPv4-адрес или домен вашего сервера (для теста Globalping)
SERVER_HOST=198.51.100.1
```

### 4. Запуск в режиме разработки

```bash
bun run dev
```

Откройте диалог с ботом в Telegram и отправьте команду `/start`.

## 🤖 Запуск в продакшене (Systemd)

Для бесперебойной работы бота в фоновом режиме настройте службу `systemd`.

1. Узнайте точный путь к бинарнику Bun:

```bash
which bun
# Обычно: /root/.bun/bin/bun или /usr/local/bin/bun
```

2. При необходимости отредактируйте `ExecStart` в файле `awg-bot.service`:

```ini
[Unit]
Description=AmneziaWG Telegram Admin Bot
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/awg-bot
ExecStart=/root/.bun/bin/bun run src/index.ts
Restart=always
RestartSec=5
EnvironmentFile=/opt/awg-bot/.env

[Install]
WantedBy=multi-user.target
```

3. Установите и запустите службу:

```bash
cp awg-bot.service /etc/systemd/system/awg-bot.service
systemctl daemon-reload
systemctl enable --now awg-bot
```

4. Проверка статуса и просмотр логов:

```bash
# Статус службы
systemctl status awg-bot

# Просмотр логов в реальном времени
journalctl -u awg-bot -f
```

## 📱 Команды и навигация в боте

| Команда | Описание |
|---|---|
| `/start`, `/menu` | Открыть главное интерактивное меню |
| `/clients` | Показать список клиентов с пагинацией |
| `/add` | Запустить FSM-диалог создания нового клиента |
| `/stats` | Показать текущий статус интерфейса и трафик пиров |
| `/check` | Запустить локальную диагностику AmneziaWG |
| `/ping` | Запустить тест доступности сервера из РФ через Globalping |
| `/backup` | Создать резервную копию и отправить архив `.tar.gz` |
| `/cancel` | Прервать текущий активный диалог |

### Инлайн-управление клиентом:
* **`📥 Скачать QR и конфиг`** — повторно генерирует QR-код в RAM и отсылает файл `.conf`.
* **`🗑 Удалить`** — открывает окно подтверждения и производит удаление пира из интерфейса.

## 🔍 Диагностика и устранение неполадок

1. **Бот не отвечает на сообщения:**
   - Убедитесь, что ваш Telegram User ID точно совпадает со значением `ADMIN_ID` в файле `.env`.
   - Проверьте логи через `journalctl -u awg-bot -f`. При несовпадении ID бот молча отсекает запросы.

2. **Ошибка при вызове команд AWG (`command not found`):**
   - Убедитесь, что скрипт `manage_amneziawg.sh` доступен по указанному в `AWG_SCRIPT` пути и имеет права на исполнение (`chmod +x /usr/local/bin/manage_amneziawg.sh`).

3. **Ошибка отправки QR-кода:**
   - Убедитесь, что клиентская конфигурация содержит валидные текстовые данные. QR-генерация происходит в памяти через `qrcode.toBuffer` и не требует записи на диск.

4. **Тест доступности выдает ошибку:**
   - Проверьте, что в параметре `SERVER_HOST` указан реальный публичный IP-адрес или валидный домен, а не `127.0.0.1`.
